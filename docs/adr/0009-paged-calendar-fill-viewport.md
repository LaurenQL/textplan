# ADR 0009: 日历分页与窗口占满

## 状态

已接受

## 背景

[ADR 0008](0008-continuous-calendar-scrolling.md) 把日历改成了连续滚动条带。部署到真实 vault 后被用户推翻：需要的是「窗口里永远展示一个完整的月/周」，不要任何滚动。

连续滚动的实现代价也很明确：周行必须用固定像素行高才能连续排列，日历因此失去随窗口高度自适应的能力，超出面板后出现滚动条，星期列头被挤压换行。

## 决策

日历回到**分页**模型，并进一步要求**铺满视口**：

### 一屏一个周期

视图状态只保留一个 `displayedDate`：月模式表示当前展示的月份，周模式表示当前展示周内的任意一天。一次渲染只产生一个周期的日期格，不预生成相邻范围。

### 铺满可用高度，不出现滚动条

日历容器用 CSS Grid 铺满工具栏以下的全部高度，`overflow: hidden`：

```text
月视图       ：grid-template-rows: auto repeat(6, minmax(0, 1fr))   列头 + 6 个等高周行
周视图·横向  ：grid-template-rows: auto minmax(0, 1fr)              列头 + 1 个占满高度的周行
周视图·纵向  ：grid-template-rows: repeat(7, minmax(0, 1fr))        7 天等分，无列头
```

行高由 `1fr` 等分决定，**不设任何固定行高**。窗口或侧边栏尺寸变化时，格子高度自动跟随，`ResizeObserver` 触发 `+x` 折叠重算。

月视图固定 6 行（`createMonthGrid` 返回 42 格），用上下月日期补齐首尾不完整的周，保证不同月份的行高一致、翻页时布局不跳动。

### 翻页

上一个 / 下一个按钮直接修改 `displayedDate` 并重新渲染：月模式 `addMonths(±1)`，周模式 `addDays(±7)`。「今天」回到今天所在的月或周。月/周切换时重置到当前月 / 当前周。

不注册任何 `touchstart` / `touchend` / `wheel` 监听——去掉手势不需要连续滚动，分页同样可以做到。

## 后果

### 正面

- 用户的心理模型与界面一致：一屏就是一个月，或一个周。
- 布局完全自适应窗口和侧边栏尺寸，不存在固定行高导致的溢出或滚动条。
- 一次只读取一个周期的日记文件（月视图 42 天，周视图 7 天），而不是 ADR 0008 的约 735 天，打开和翻页都更快。
- 视图状态回到单一 `displayedDate`，不需要滚动锚点、`IntersectionObserver` 或标题跟随逻辑。

### 负面

- 无法同时看到跨月边界两侧的内容；查看相邻月份必须翻页。
- 窗口高度很小时，月视图 6 行等分后每格可能只容得下一条任务，`+x` 会较频繁出现。这是可接受的取舍：宁可折叠，也不出现滚动条。
- 周视图纵向布局在窗口很矮时，7 行等分同样会压缩单行高度。

### 风险缓解

- 尺寸相关的值集中为 CSS 变量，移动端只覆盖变量即可获得更紧凑的字号和行高。
- `+x` 折叠按实际测量的可用高度计算，保证任何行高下都不出现半行截断或文字堆叠。
