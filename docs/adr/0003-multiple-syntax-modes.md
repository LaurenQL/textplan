# ADR 0003: 多语法模式支持

## 状态

已接受

## 背景

用户对 todo 标记语法有不同的偏好：

1. **Markdown 标准用户**：习惯使用 `- [ ]` / `- [x]`，与其他工具和导出格式兼容性最好
2. **简洁标记用户**：喜欢更轻量的标记，如 `* todo`，输入速度快
3. **自定义用户**：想要使用自己习惯的标记符号

同时，ADR 0002 中记录的 `* ✓` 方案虽然解决了斜体冲突问题，但星号模式在编辑器内仍显示为列表圆点，视觉上与用户预期有差距。

## 决策

实现三种语法模式，让用户自由选择：

### 1. Markdown 原生模式（默认）

```md
- [ ] todo
- [x] todo
```

**选择为默认的理由**：
- Obsidian 原生完整支持，零额外实现成本
- 与其他插件（Tasks、Dataview）和导出工具（Pandoc、Hugo）兼容性最好
- 学习成本最低，几乎所有 Markdown 用户都熟悉
- 视觉渲染完美，Obsidian 已有交互式 checkbox

### 2. 星号模式

```md
* todo
* ✓ todo
```

**保留的理由**：
- 输入速度快，单字符标记
- 原 TextPlan 的特色语法，已有用户基础
- 虽然编辑器内显示为列表，但功能完整（解析、切换、归档）

**不做编辑器视觉改动的理由**：
- 与 Obsidian 原生列表渲染系统对抗，技术风险高
- 优先保证功能稳定性，视觉细节是次要的
- 用户可以选择 Markdown 原生模式获得更好的视觉体验

### 3. 自定义模式

用户在设置中定义 `customOpen` 和 `customDone` 标记，例如：

```md
>> todo
>>x todo
```

**提供的理由**：
- 满足特殊需求（如非拉丁语言用户）
- 与其他工具的个人工作流集成
- 增加插件灵活性

### 架构设计

**Core 层参数化**：
所有 todo 解析、切换、归档函数接受 `TodoSyntaxConfig` 参数：

```typescript
export interface TodoSyntaxConfig {
  mode: "markdown" | "asterisk" | "custom";
  customOpen?: string;
  customDone?: string;
}
```

**跨模式归档兼容**：
用户切换语法模式后，旧模式的已完成任务仍需能被归档。实现专门的 `parseCompletedTodoAnyMode()` 函数，识别所有模式的已完成标记。

**动态切换支持**：
使用 CodeMirror 6 的 `Compartment` 系统，用户在设置页切换模式时，编辑器扩展动态重配置，无需重启。

## 后果

### 正面

- 用户自由度高，可选择最适合自己的语法
- Markdown 原生作为默认，降低新用户学习成本
- 与 Obsidian 生态兼容性好
- 架构参数化，未来易扩展新语法

### 负面

- 增加了实现复杂度（三套解析和渲染逻辑）
- 测试覆盖面增加
- 用户之间的数据格式不统一（但 Markdown 纯文本本质上允许这种多样性）

### 风险缓解

- Core 层测试覆盖所有语法模式
- 跨模式归档兼容确保用户切换模式后不丢失旧数据
- 文档明确说明默认模式和推荐模式
