# ADR 0007: 月/周双日历模式

## 状态

已接受。分页与铺满视口的行为见 [ADR 0009: 日历分页与窗口占满](0009-paged-calendar-fill-viewport.md)。

## 背景

MVP 只有月视图。月视图适合"一眼扫过整月"，但单个日期格能容纳的任务很少——尤其在左侧边栏的窄宽度下（见 [ADR 0006](0006-left-sidebar-default-placement.md)），一格常常只放得下两三行。

用户对"本周"的关注密度远高于对"本月"的关注密度：当天和未来几天的任务需要看清全文，而不是被折叠成 `+x`。

参考形态是 NotePlan 的周视图：7 天纵向排列成 7 个横向区块，每个区块横跨整个面板宽度，因此每天能显示的任务比月视图的小方格多得多。

## 决策

在同一个 TextPlan View 内提供**月视图**和**周视图**两种模式，工具栏切换，默认月视图。

### 为什么是模式切换而不是两个 View

- 两种模式的数据来源、筛选规则、点击行为、溢出规则完全一致，只有日期布局不同
- 拆成两个 `ViewType` 会导致选中日期、滚动位置等状态无法共享，用户切换时上下文丢失
- 侧边栏里多一个标签页对用户是负担，而不是便利

### 为什么周视图提供纵向和横向两种布局

最初的方案只做纵向列表，理由是横向 7 格在窄侧边栏里每格只有约 1/7 的宽度，任务文本会被截断到看不出内容——这正是月视图已有的问题，横向周视图不解决任何事。

但这个论证只在**窄侧边栏**这个前提下成立。ADR 0006 明确了 TextPlan View 不锁定位置，用户可以把它拖到主区域或较宽的面板；在那种宽度下，横向 7 格是一个合理甚至更熟悉的形态（等同于月视图的一整行）。

因此改为两种布局都提供，由设置项 `weekViewLayout` 决定：

- **横向（默认）**：7 天排成一行，形态等同月视图的一行，但该行占满全部可用高度
  - 在宽面板下更接近传统日历的视觉习惯
  - 用户的实际使用反馈表明，横向总览是更常用的默认入口
  - 因为独占整个视口高度，单格能显示的任务数远多于月视图
- **纵向**：7 天从上到下排列，每天占满面板宽度，7 行等分可用高度
  - 每行必须显示「日期 + 星期 + 内容」，因为纵向布局没有列头
  - 任务文本可以完整显示
  - 单日区块宽度更大，长任务不易被截断

原先“窄栏截断因此纵向默认”的论证不再适用；窄栏下用户仍可主动切换到纵向布局获得更完整的任务文本。

### 架构上的共用

Core 层新增 `weekGrid.ts`，`createWeekGrid(date, weekStartDay)` 返回与 `createMonthGrid` **同构**的 `DayCell` 数组（只是长度为 7）。UI 层因此可以：

```text
renderCalendar()
  月      ：createMonthGrid() → 网格容器（列头 + 6 个等高周行）
  周·纵向 ：createWeekGrid()  → 纵向容器（7 天等分高度，无列头）
  周·横向 ：createWeekGrid()  → 网格容器（列头 + 1 个占满高度的周行）
  三者都调用同一个 renderDayCell()
```

布局的差异只落在外层容器的 CSS 上，不落在数据、事件或筛选逻辑里。横向周视图不需要新的数据源，也不需要新的格子渲染函数——它就是月视图容器 + 周数据。这保证三种布局的行为不会随时间漂移成三套。

### 状态持久化

新增两个设置项：

- `defaultCalendarMode`（默认 `"month"`）——月还是周。工具栏切换只影响当前 View；切到月展示当前月，切到周展示当前周（详见 ADR 0009）。
- `weekViewLayout`（默认 `"horizontal"`）——周视图用纵向还是横向。只在设置页配置，不放进工具栏，避免窄栏下控件过多。

## 后果

### 正面

- 用户可以按需在"总览"和"本周细节"之间切换
- 周视图纵向布局缓解了窄侧边栏下任务显示不全的问题
- 横向布局让把视图拖到宽面板的用户获得更熟悉的日历形态
- 共用渲染函数，三种布局的行为天然一致
- `weekGrid` 是纯函数，可单元测试，也可被未来的独立版复用

### 负面

- 工具栏控件增多，需要在窄栏下仍然排得下
- 上一个/下一个按钮的语义随模式变化（切月 vs 切周），需要在图标或提示上体现
- 三种布局（月 / 周·纵向 / 周·横向）意味着三套容器 CSS，需要防止样式互相污染
- 横向周视图在窄侧边栏下体验较差，属于用户可主动选择的次优配置，需要在设置项说明中提示

### 风险缓解

- 分段控件用紧凑样式，必要时只显示「月」「周」两个字
- 周视图布局放在设置页而不是工具栏，避免窄栏下控件堆积
- 按钮的 `aria-label` 和 tooltip 按当前模式动态生成，并进入 i18n
- 横向周视图直接复用月视图的容器类名与格子样式，只覆盖列数和换行行为，避免第三套独立 CSS
- 纵向布局的 CSS 用独立容器类名作用域隔离
