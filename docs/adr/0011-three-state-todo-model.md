# ADR 0011：三态任务模型（未完成 / 已完成 / 已放弃）

日期：2026-09-17

状态：已接受

## 背景

原来任务只有两种状态：未完成和已完成。实际使用中出现了第三种情况 —— 一件事**决定不做了**。

用两态模型处理这种情况，只有两个选择：

- 标成已完成：失真。它没做，而且会混进 `## Done` 归档区，污染「我完成了什么」的记录
- 直接删掉：丢信息。过一段时间回看时，不知道这件事当初是做了、还是放弃了、还是压根没写过

用户需要的是「留下痕迹，但不再占据注意力」。

## 决策

任务改为三态：`open` / `done` / `abandoned`。

**语法**（各模式规范输出）：

| 模式 | 未完成 | 已完成 | 已放弃 |
|---|---|---|---|
| Markdown 原生 | `- [ ] todo` | `- [x] todo` | `- [-] todo` |
| 星号 | `* todo` | `* ✓ todo` | `* x todo` |
| 自定义 | `customOpen` | `customDone` | `customAbandoned` |

自定义模式未配置放弃标记时，降级为 Markdown 原生写法 `- [-]`。

**切换是三态环**，点击和 `CMD+D` 都走同一个环：

```text
未完成 → 已完成 → 已放弃 → 未完成
```

选了环而不是「两个独立命令」，是因为点击标记只有一个手势可用，再加一个命令会让「点一下会变成什么」变得不可预测。环的代价是从 `done` 回 `open` 要点两次，可以接受。

**已放弃在「显示」上同已完成，在「归档」上同未完成：**

| 行为 | 未完成 | 已完成 | 已放弃 |
|---|---|---|---|
| 编辑器内弱化 + 删除线 | 否 | 是 | 是 |
| 显示在日历 | 是 | 否 | 否 |
| 被 `CMD+SHIFT+A` 归档进 `## Done` | 否 | 是 | **否** |
| 记 `@done(...)` 时间 | 否 | 可选 | 否 |

放弃任务不归档，是这个 ADR 最容易被实现漏掉的一条。理由：`## Done` 的语义是「我完成了这些」，把放弃的事混进去会让归档区不再可信。放弃任务留在原位置，靠删除线表达「这条已经结束了」。

切换到放弃时移除 `@done(...)`：放弃不是完成，不该有完成时间。

## 后果

**好处：**

- 「不做了」有了准确表达，不再被迫在失真和丢信息之间选
- 归档区保持干净，`## Done` 仍然只代表真正完成的事
- 日历不被已结束的事占位

**代价与风险：**

- `Todo.completed` 的定义是 `state !== "open"`，它同时覆盖 `done` 和 `abandoned`。判断「要不要画删除线」用它是对的，判断「要不要归档」用它就错。归档实现最初就踩了这个坑，把放弃任务一起归进了 `## Done`
- 缓解措施：归档只认 `state === "done"`，并在 `tests/todoArchive.test.ts` 用四个测试锁住边界（星号放弃不归档、Markdown 放弃不归档、只有放弃任务时不创建 Done 区块、跨语法模式下放弃也不归档）
- 三态环让「取消完成」需要点两次，是有意接受的取舍
