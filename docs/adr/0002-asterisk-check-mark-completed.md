# ADR 0002：完成标记使用 `* ✓`（带空格）

## 状态

已接受

## 背景

TextPlan 的默认 todo 语法需要区分未完成与已完成任务。早期实现使用 `*[x] todo` 作为已完成标记。

但这个写法在 Obsidian Live Preview 中不稳定：CommonMark 将 `*[x]` 解析为 emphasis（斜体），因为它符合“`*` 后紧跟非空白字符”的 emphasis 规则。结果 Obsidian 把 `*[x]` 的星号当斜体起始符渲染，编辑器内的斜体 token（`.cm-em`、`.cm-formatting-em`）与 CSS 覆盖互相冲突，即使覆盖了 `font-style`，光标、选区、Live Preview 状态仍可能异常。

尝试过以下几种方案：

- 用 CodeMirror widget 替换 marker：光标附近出现重复 `*`，显示不稳定。
- 纯 CSS 覆盖 `.cm-em` / `.cm-formatting-em`：依赖 Obsidian 内部 token，不够稳定。
- 给整个 TextPlan 日记文件加编辑器 class 缩小作用域：能限制范围，但无法解决与 emphasis 解析的冲突本身。

## 决策

已完成任务标记改用 **`* ✓`**（`*` 与 `✓` 之间有一个空格）：

```md
* todo
* ✓ todo
```

选择带空格的原因是：

- `*` 后是空格，不满足 CommonMark emphasis 起始条件（`*` 后必须紧跟非空白字符才会触发），因此 `* ✓` 不会被解析为斜体。
- 行为上 `* ✓` 与 `* todo` 一样，是一个 Markdown 无序列表项，只需沿用处理列表圆点的方式隐藏圆点即可，与未完成任务的处理一致。
- 不建立新的解析冲突，渲染稳定性由语法本身保证，而非依赖 CSS 覆盖。

读取兼容：

- 解析时仍识别旧版已完成写法 `*[x] todo`（以及大小写不敏感的 `*[X]`），保证已有任务数据可识别。
- 读取和切换时兼容未完成任务写法 `*todo`（无空格）。
- 规范输出统一为 `* ✓ todo`；切换已完成任务恢复为 `* todo`。

## 影响

收益：

- 从根源上消除 emphasis 解析冲突，编辑器渲染更稳定。
- 已完成标记与未完成标记同为无序列表项，视觉处理共用一套逻辑。
- 保留对旧 `*[x]` 的读取兼容，不破坏已有数据。

取舍：

- 已完成标记从 `*[x]` 变为 `* ✓`，视觉标记形式改变，需要同步更新 PRD、架构文档、实现计划、README 和所有示例。
- 仍需要编辑器扩展隐藏 Markdown 列表圆点、为已完成文本加删除线和弱化样式。
- 若用户已有任务写成 `*[x]`，切换状态时会被规范化为 `* ✓`，源码文本会发生变化。
