# ADR 0014：按日期分组的 Todo（`### YYYY-MM-DD`）

日期：2026-11-15

状态：已接受

## 背景

日记里的 todo 只有一种归属方式：写在哪个文件里，就属于哪一天。这条规则简单，但和真实用法冲突。

典型场景是提前计划：

```md
textplan/20261110.md

- [ ] 今天的事
- [ ] 20 号交房租
- [ ] 25 号出差
```

后两条在 11 月 10 日写下，但它们实际上是 20 号和 25 号的事。按「文件归属」规则，它们会一直挂在 10 号格子里，到 20 号那天又什么都不显示 —— 日历反而看不出哪天才是真正忙的那天。

另一种做法是到时候再把 todo 抄到当天的日记里。这要求用户记得回来搬运，搬运过程中还可能漏掉，且原始记录和最终执行分成两处，很难追溯。

## 决策

用**三级标题**给一组 todo 指定生效日期，日历按标题日期而不是文件日期显示。

```md
### 2026-11-20
- [ ] 交房租
- [ ] 预约牙医
```

### 为什么是标题而不是行尾标记

也考虑过行尾标记（`- [ ] 交房租 @date(2026-11-20)`），最终选了标题，理由是：

- **可读性**：一组任务聚在一个标题下，编辑器大纲（Outline）里直接可见，滚动定位方便。行尾标记在长文件里要一行行找。
- **可编辑性**：改日期只需改一个标题，不用改每条 todo。
- **不污染行内容**：行尾标记会被归档逻辑、完成时间戳（`@done(...)`）一起处理，语义容易混在一起。标题是结构，标记是内容，分开更干净。
- **与已有写法一致**：PRD 5.5 的嵌套 todo 已经依赖缩进和列表结构，标题分组是同一套心智模型的延伸。

代价是语法更「重」—— 必须写三行才能标注一条跨天任务。但跨天计划通常本来就是成组的，这个代价可以接受。

### 语法约束

- 必须是**三级**标题（恰好三个 `#`），`##` 和 `####` 都不生效
- 日期必须是补零的 `YYYY-MM-DD`，且只能有日期，不能带备注
- 遇到下一个任意级别标题（`#` 到 `######`）时分组结束
- `## Done` 区块内的一切都不参与分组 —— 归档区是历史，不该再往未来排

严格匹配是有意为之：标题同时是给人读的正文，宽松匹配会把 `### 会议记录 2026-11-20` 这类标题误判成日期分组。

### 归属与排除

标题下的 todo **归属标题日期，并从文件自身那天排除**。

这条排他规则很关键：如果不过滤，写在 `20261110.md` 里、标了 `### 2026-11-20` 的任务会同时出现在 10 号和 20 号，用户会以为有两件事。实现上用 `lineNumbers` 集合记住哪些行已经被分组，渲染文件自己那天时跳过这些行。

### 分层

- `core/datedSection.ts` —— 纯文本解析，输入文件内容，输出「日期 → todo 列表」和「已分组行号集合」。不依赖 Obsidian，可纯函数测试。
- `obsidian/datedTodoIndex.ts` —— 跨文件索引。扫 vault 里所有能识别成日记的文件，合并各文件的解析结果。

日期标题的解析不认识 Obsidian API，也不读磁盘，和 `core/ics.ts` 的分层思路一致。

### 索引与缓存

跨文件意味着每次渲染都可能要读几十上百个文件。处理方式：

- 索引结果按 `path` 缓存，附带 `mtime`
- 每次重建只重新解析 mtime 变过的文件，未改动的复用缓存
- 文件删除时清掉对应缓存条目
- vault 的 `modify` / `create` / `delete` / `rename` 事件触发索引失效

不做「每次渲染全量重读」，因为日历每次翻页、每次点击都会渲染一遍，全量读在几百篇日记的 vault 里会明显卡顿。

### 与其他规则的关系

- 分组 todo 和当天日记的 todo **合并后**一起排序：未完成在前，已完成在后，同状态保持文件内顺序
- 合并后一起参与 7.1 的 `+x` 溢出折叠
- 已放弃的 todo 即使写在日期标题下，也不显示
- 多文件分组到同一天时，按文件路径排序拼接，保证顺序稳定 —— 遍历 `Map` 的顺序不保证，不排序会导致每次渲染顺序可能变化

## 后果

**好处：**

- 提前写下的计划能显示在正确日期，不用到时候搬运
- 一个文件可以同时承载「今天要做」和「这几天要做」，日记文件数量不会因为提前规划而膨胀
- 解析是纯函数，`tests/datedSection.test.ts` 覆盖了分组、边界、Done 区块、星号模式和畸形日期六类情况
- 标题在编辑器和 Obsidian 大纲里都是原生结构，不需要额外装饰

**代价与风险：**

- 首次渲染要读一遍全部日记文件（之后靠 mtime 增量）。几百篇日记的 vault 第一次打开会有可感知的读取延迟
- 日期标题是「约定而不是机制」：用户改了标题格式（比如写成 `### 2026/11/20`），分组静默失效，任务退回文件自身那天，不会报错也不会提示
- 标题本身会被日历之外的插件（大纲、目录类插件）当作普通三级标题展示，可能显得意外 —— 但对用户来说它就是正文结构，可以接受
- 不支持跨文件引用：`### 2026-11-20` 只对本文件内、本标题下的 todo 生效
